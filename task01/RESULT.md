## 5. Проверка за 5 минут
Действия (на сервере: `cd /opt/devops/task01 && ./scripts/check.sh`; вручную):
1. `curl -I https://a1.fdghyt.com/review-user/demo` — анонимный запрос.
2. Войти под `review-user`, открыть `demo`, убедиться, что `check.txt` содержит `gitea-test-v1`.
3. `git clone https://a1.fdghyt.com/review-user/demo.git` и `git log --format=%H`.
4. Остановить исходный проект (`cd configs && docker compose stop`), восстановить копию (`./scripts/restore.sh task01-restore /opt/task01-restore backups/<архив>.tar.gz.gpg files`), открыть `https://danil1.fdghyt.com` и повторить пункт 3.

Ожидаемый результат:
- пункт 1: `HTTP 404` (анонимный доступ закрыт);
- пункт 2: пользователь входит, `demo` содержит два коммита;
- пункты 3–4: в истории есть коммит `7239eeb94281a16f4c6a7c5c84d6c37861745cb8`, в том числе в восстановленной копии.

## Проблемы и ограничения
- Зашифрованные архивы копий лежат только на сервере в `backups/`; `*.gpg` исключён из git, так как по условию копии с данными пользователей хранятся отдельно от архива с исходными файлами. Пароль архива в `secrets/credentials.txt`, передаётся отдельно.
- Hash `7239eeb…` относится к репозиторию `demo` на текущем стенде; после проверок в репозиторий добавлялись тестовые коммиты поверх него.
- Восстановленная копия работает без своего Caddy: её публикует общий Caddy на `danil1.fdghyt.com`; проект Compose должен называться `task01-restore`.
