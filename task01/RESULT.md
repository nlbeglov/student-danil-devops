## 5. Проверка за 5 минут
Действия (быстрая автоматическая проверка на сервере: `cd /opt/devops/task01/configs && ../scripts/check.sh`):
1. `curl -I https://git.politblocks.com/review-user/demo`.
2. Войти под `review-user`, открыть репозиторий `demo`, убедиться, что `check.txt` содержит `gitea-test-v1`.
3. `git clone https://git.politblocks.com/review-user/demo.git` и `git log -1 --format="%H"`.
4. Остановить исходный проект (`docker compose stop`), запустить восстановленную копию и повторить пункт 3.

Ожидаемый результат:
- пункт 1: `HTTP 404` (анонимный доступ закрыт);
- пункт 2: пользователь входит, `demo` содержит два коммита;
- пункты 3–4: hash последнего коммита совпадает с `3c7bc3b218b336b11f43ac898848f1726656ee64`, в том числе в восстановленной копии.

## Проблемы и ограничения
- Требование 6 выполнено частично: в [Требование 6](<evidence/Требование 6.md>) нет вывода `check.sh` после перезагрузки VPS. Выполнить `sudo reboot`, затем `./scripts/check.sh` и приложить вывод.
- Зашифрованный архив резервной копии `evidence/backup-2026-09-17_1109.tar.gz.gpg` лежит рядом с доказательствами только на рабочем компьютере: `*.gpg` исключён из git (`.gitignore`), по условию задания копии с данными пользователей хранятся отдельно от архива с исходными файлами. Пароль архива передаётся отдельно.
- Время копирования и восстановления для заполнения таблицы выше выводят `backup.sh` и `restore.sh` в последней строке.
