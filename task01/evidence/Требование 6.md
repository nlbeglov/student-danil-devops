# Требование 6
> Подготовить scripts/backup.sh, scripts/restore.sh и scripts/check.sh. Проверить сохранность данных после перезагрузки VPS. Для восстановления явно указать проект, новые тома, входную копию и способ передачи секретов.

## Скрипты

| Скрипт | Использование | Что делает |
|---|---|---|
| [backup.sh](../scripts/backup.sh) | `./scripts/backup.sh [каталог проекта]` | останавливает запись, дамп PostgreSQL, файлы Gitea, конфигурация, шифрование gpg; пароль архива в `secrets/credentials.txt` |
| [restore.sh](../scripts/restore.sh) | `./scripts/restore.sh <имя проекта> <новый каталог> <архив.tar.gz.gpg> <input\|files>` | собирает отдельный проект Compose с новыми томами и поднимает его |
| [check.sh](../scripts/check.sh) | `./scripts/check.sh [каталог проекта] [input\|files]` | контейнеры, автозапуск, данные, HTTPS и редирект, закрытые порты, анонимный 404, вход, clone, hash коммита |

Параметры `restore.sh`: проект и новые тома задаются именем проекта и новым каталогом (`<каталог>/data/gitea`, `<каталог>/data/postgres`), входная копия — файл `.tar.gz.gpg`, секреты — `input` (ввод с клавиатуры) или `files` (`credentials.txt` и готовый `.env`).

## Порядок проверок
```bash
cd /opt/devops/task01
./scripts/backup.sh                                   # копия в backups/
(cd configs && docker compose stop)                   # исходный проект остановлен
./scripts/restore.sh task01-restore /opt/task01-restore backups/backup-<время>.tar.gz.gpg files
./scripts/check.sh /opt/task01-restore files          # вход, clone, совпадение исходного hash
(cd configs && docker compose up -d)                  # основной стенд снова запущен
```

## Проверка после перезагрузки VPS
```bash
sudo reboot
# после загрузки, через 1–2 минуты:
cd /opt/devops/task01/configs && ../scripts/check.sh
```
Шаг `[2/6]` показывает время загрузки системы и время старта контейнеров (разница не больше нескольких минут: запущены автоматически, `restart: always`), шаг `[3/6]` — что данные на месте, шаг `[6/6]` — что вход и hash коммита прежние.
