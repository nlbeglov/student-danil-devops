# Требование 5
> Восстановить сервис в отдельном проекте Compose с новыми томами. Допускается тот же VPS. Для проверки использовать отдельный адрес либо локальный порт через SSH-туннель. Восстановленный проект должен работать при остановленном исходном проекте.
### Был подготовлен скрипт работы с комментариями
```
# останавливаем основной докер 
cd /opt/task01/configs
docker compose stop
# переносим архив в отдельную папку (имитируем полное восстановление с внешнего хранилища)
mkdir /opt/task01/restore-staging
cd /opt/task01/restore-staging
cp /opt/task01/backup-*.tar.gz.gpg /opt/task01/restore-staging
# расшифровываем паролем из файла и распаковываем
gpg -d backup-*.tar.gz.gpg > backup.tar.gz
tar -xzf backup.tar.gz
# создаем env
cp .env.example .env
```
> [!warning]
>  По хорошему нужно заменить все данные в  `/opt/task01/restore-staging/backup/.env` (так как он будет пустым из-за копии example) и соответсвенно домен в. Так и было сделано на тестовом стенде  

> [!tip]
> Однако для быстрого теста можно не делать действия из warning, а просто прописать `cp /opt/task01/.env /opt/task01/restore-staging/backup/.env` и наслаждаться
```
cd /opt/task-01/restore-staging/backup
# поднимаем только базу и восстанавливаем дамп
docker compose up -d db
sleep 5
docker compose exec -T db pg_restore -U gitea -d gitea --clean --if-exists < gitea_db.dump
# распаковываем файлы Gitea
tar -xzf gitea-data.tar.gz -C .
# запускаем Gitea и Caddy
docker compose up -d server caddy
docker compose logs -f server
# Теперь проверяем работоспособность сравнением хеша последнего коммита
git clone https://test0.politblocks.com/review-user/demo.git /tmp/restore-clone-test
cd /tmp/restore-clone-test
git log -1 --format="%H"
```
