## Схема сервисов
Docker Compose проект из трёх сервисов на одном VPS:

- **caddy** (`caddy:2.11.4`) — reverse proxy, терминирует HTTPS, проксирует запросы на `server:3000`.
- **server** (`docker.gitea.com/gitea:1.27.3`) — Gitea, Git-сервис. Открытая регистрация отключена (`GITEA__service__DISABLE_REGISTRATION=true`).
- **db** (`postgres:14`) — база данных Gitea, доступна только во внутренней сети Compose (`gitea`), портов наружу не публикует.

Данные хранятся в bind-mount томах `./gitea` (репозитории и файлы Gitea) и `./postgres` (данные PostgreSQL) — сохраняются между перезапусками и перезагрузками VPS.
## Порты
| Порт | Назначение | Доступность |
|---|---|---|
| 80 | HTTP → редирект на HTTPS | публично |
| 443 | HTTPS (Caddy → Gitea) | нпублично |
| 22 | SSH к VPS | публично |
| 3000 | Gitea (внутри контейнера) | только внутренняя сеть `gitea` |
| 5432 | PostgreSQL | только внутренняя сеть `gitea` |

Проверено `nc`/`curl`: 3000 и 5432 снаружи не отвечают (timeout), см. [Требование 3](<evidence/Требование 3.md>).

## Зависимости от common
Задание выполнено как самостоятельный проект, отдельного `common/` не использует. Caddy данного задания обслуживает только домен Gitea (`git.politblocks.com`).
## Ручные дейтсвия
- Создание пользователей `review-admin` и `review-user` выполнено вручную через `docker compose exec -u git server gitea admin user create ...` (команды в `evidence/Требование 1.md` и `Требование 2.md`).
- Создание репозитория `demo` и двух коммитов выполнено вручную с локальной машины (см. `evidence/Требование 2.md`).
- Перед снятием резервной копии Gitea останавливается вручную (`docker compose stop server`) и запускается обратно после копирования.
- При восстановлении на новом стенде домен в `Caddyfile` и значения `.env` нужно поправить вручную под целевой адрес (см. предупреждение в `evidence/Требование 5.md`).
