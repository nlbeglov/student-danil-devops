# Требование 4
> Доставлять сообщения через собственный ntfy в браузер или на телефон. Включить авторизацию ntfy и закрыть анонимную публикацию и чтение тестового канала. Интерфейс Uptime Kuma также защитить входом. Секреты подключения хранить вне архива исходных файлов.

## Авторизация ntfy и Kuma
Анонимный доступ закрыт (`NTFY_AUTH_DEFAULT_ACCESS=deny-all`, регистрация выключена); пользователи и права создаёт [setup-secrets.sh](../monitor-vps/scripts/setup-secrets.sh): `reader` — чтение топика, `kuma` — запись, `admin`. Интерфейс Kuma защищён входом: администратор создан сразу после запуска. Секреты хранятся в `monitor-vps/secrets/credentials.txt` вне git.

Результат (06.10.2026):
```
anon read:    403
anon write:   403
reader read:  200
reader write: 403
kuma UI без входа (HTTP): 200 -> 
user admin (role: admin, tier: none)
- read-write access to all topics (admin role)
user kuma (role: user, tier: none)
- write-only access to topic monitor-alerts
user reader (role: user, tier: none)
- read-only access to topic monitor-alerts
user * (role: anonymous, tier: none)
- no topic-specific permissions
- no access to any (other) topics (server config)
```
Страница `/dashboard` Kuma отдаёт оболочку приложения (HTTP 200), все данные и действия требуют входа администратора (аутентификация выполняется при подключении к серверу Kuma).
