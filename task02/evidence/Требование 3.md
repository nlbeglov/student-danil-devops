# Требование 3
## 1. Пайплайн
Workflow [.github/workflows/ci-cd.yml](../.github/workflows/ci-cd.yml), триггер — `push` в `main`. Три job'а строго по цепочке:
```
test  →  build (needs: test)  →  deploy (needs: build)
```
- `test` — `pip install -r requirements.txt` + `python -m pytest tests/ -v`. Если упал — `build` и `deploy` не запускаются (job'ы GitHub Actions запускаются только если все `needs` завершились успехом).
- `build` — логин в GHCR (`docker/login-action`), сборка и публикация `docker/build-push-action` с тегом `ghcr.io/<repo>:<commit sha>`, вывод digest в `outputs.image_digest`.
- `deploy` — запускает [scripts/ci-deploy.sh](../scripts/ci-deploy.sh) по SSH с `IMAGE_REF=ghcr.io/<repo>@<digest>` (не по тегу!) и `APP_VERSION=<commit sha>`, затем проверяет `/health` и `/version` уже на сервере.

Публикация всегда идёт по **digest**, не по тегу `latest` — тег в образе совпадает с SHA коммита, поэтому по логам GitHub однозначно видно, из какого коммита собран каждый образ.
