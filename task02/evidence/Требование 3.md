# Требование 3
> Настроить GitHub Actions: тесты → сборка образа → публикация в GHCR → доставка на VPS. При падении тестов публикация и доставка не выполняются. Развёртывать конкретный digest образа; связать его с commit исходного кода.

## 1. Пайплайн
Workflow [.github/workflows/ci-cd.yml](../.github/workflows/ci-cd.yml), триггер — `push` в `main`. Три job'а строго по цепочке:
```
test  →  build (needs: test)  →  deploy (needs: build)
```
- `test` — `pip install -r configs/requirements.txt` + `python -m pytest tests/ -v`. Если упал — `build` и `deploy` пропускаются (`needs`).
- `build` — логин в GHCR встроенным `GITHUB_TOKEN`, сборка по [configs/Dockerfile](../configs/Dockerfile) и публикация `docker/build-push-action` с тегом `ghcr.io/<repo>:<commit sha>` и метками OCI (`org.opencontainers.image.revision` = commit); digest передаётся дальше в `outputs.image_digest`, а в сводку прогона пишется строка «версия — commit — digest».
- `deploy` — [scripts/ci-deploy.sh](../scripts/ci-deploy.sh) по SSH с `IMAGE_REF=ghcr.io/<repo>@<digest>` (не по тегу) и `APP_VERSION=<commit sha>`, затем проверка `/health`, `/version` и сложения на сервере.

Образ привязан к исходному коду двумя способами: тег и `APP_VERSION` равны SHA коммита, а `/version` отдаёт этот же SHA.
