### Результат опыта 1
- **Время диагностики:** сбой внесён в 07:51:29, исправление начато в 07:55:19 ([faults.log](faults.log)): около **3 мин 50 с**. Короткая запись 07:50:39–07:51:02 в журнале перед опытом — пробное внесение сбоя, в замер не входит.
- **Фактический симптом:** `check.sh` во время сбоя ([incident-1-during.txt](incident-1-during.txt)): HTTPS, анонимный API, вход и clone дают **502**, при этом все 3 контейнера `Up`, а редирект http→https работает (308). То есть Caddy жив, сломан путь от него к Gitea.
- **Гипотезы:** «Gitea не работает» отвергнута (`/api/healthz` отвечает `pass`), «Gitea не достучалась до БД» отвергнута (`database:ping` = `pass`), «проблема DNS/сети» отвергнута (имя `server` разрешается в `172.24.0.2`, порт 3000 отвечает), «неверный домен/сертификат» отвергнута (HTTPS принят, 502 отдаёт сам Caddy).
- **Причина:** в Caddyfile upstream указан на порт `3001` (`reverse_proxy server:3001`), а Gitea слушает `3000`.
- **Связь ошибка → симптом:** Caddy принимает HTTPS-запрос и пытается проксировать его на `server:3001`. На этом порту никто не слушает, соединение отклоняется (`connect: connection refused` в логах Caddy), и клиент получает 502.
- **Исправление:** `./scripts/recover.sh` пересоздал Caddy с эталонным Caddyfile (`server:3000`). Данные не затрагивались.

### Результат опыта 3
- **Время диагностики:** сбой внесён в 09:47:41, исправление начато в 09:50:18 ([faults.log](faults.log)): около **2 мин 37 с**.
- **Фактический симптом:** во время сбоя HTTPS, API, вход и clone дают **502** ([incident-3-during.txt](incident-3-during.txt)); у `server` статус `health: starting`. В логах Gitea при старте: `chmod: /data/ssh/...: Read-only file system`, `chmod: /data/gitea: Read-only file system`, `chmod: /data/git: Read-only file system`.
- **Гипотезы:** «нет места на диске» отвергнута (`df -h`: свободно 50 ГБ, занято 13%); «проблема владельца/прав каталога» отвергнута: ошибка именно `Read-only file system`, а не `Permission denied`; «повреждён том/БД» отвергнута: данные на месте. Подтверждена гипотеза «том данных смонтирован только для чтения».
- **Причина:** том данных Gitea подключён с флагом `:ro` (`docker inspect`: `/data RW=false mode=ro`; `touch /data/write-test` → `Read-only file system`).
- **Связь ошибка → симптом:** Gitea при старте и в работе пишет в `/data`: права на файлы, ключи SSH, конфигурацию, репозитории. На read-only томе любая запись заканчивается ошибкой `Read-only file system` (это видно в логах), Gitea не может нормально работать, не становится здоровой, и Caddy отвечает 502.
- **Исправление:** `./scripts/recover.sh` пересоздал `server` с томом в режиме чтения-записи. Данные не менялись: после исправления тот же hash коммита и та же сумма `check.txt` ([incident-3-after.txt](incident-3-after.txt)).
