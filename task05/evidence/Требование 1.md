# Требование 1
> Развернуть Gitea, PostgreSQL и Caddy с HTTPS. Закрыть открытую регистрацию. Создать администратора review-admin, обычного пользователя review-user и его закрытый репозиторий demo с двумя коммитами. Проверить clone и push по HTTPS и отказ в анонимном доступе.
## Рабочий стенд
Были созданы конфигурационные файлы:
- [.env.example](../configs/.env.example)
- [docker-compose.yml](../configs/docker-compose.yml)
- [Caddyfile](../configs/Caddyfile)
Скрипты:
- [lib.sh](../scripts/lib.sh) - общие функции для остальных скриптов (пути, чтение .env и credentials.txt, учётные данные git, запросы к API Gitea, журнал событий). Сам не запускается, подключается через source.
- [setup-secrets.sh](../scripts/setup-secrets.sh) - одним запуском создаёт все пароли стенда (PostgreSQL, review-admin, review-user), показывает их на экране и сохраняет в secrets/credentials.txt, чтобы можно было вернуться к ним в любой момент. Пароль PostgreSQL дополнительно записывается в configs/.env (Compose подставляет его из .env). Повторный запуск не меняет уже существующие пароли.
> [!tip]
> setup-secrets.sh запускать до первого запуска стека: пароль PostgreSQL применяется только при инициализации базы. После этого менять его в .env бессмысленно потому что база уже создана со старым паролем.
- [deploy.sh](../scripts/deploy.sh) - первый запуск стека одной командой. Проверяет, что .env и пароли готовы, поднимает стек и ждёт, пока Gitea станет здоровой.
Первый запуск:
```
cd /opt/task05/configs && cp .env.example .env && nano .env
chmod +x ../scripts/*.sh
../scripts/setup-secrets.sh
../scripts/deploy.sh
```
## Демо-данные и эталон
- [prepare-demo.sh](../scripts/prepare-demo.sh) - Зачем: создаёт пользователей и закрытый репозиторий, делает два коммита через HTTPS, фиксирует эталон в evidence/baseline.txt (hash коммита + SHA-256 check.txt) и хэши конфигурации в evidence/baseline-config.sha256. Повторный запуск ничего не ломает.
- [check.sh](../scripts/check.sh) - контрольные проверки из требования 5: HTTPS, закрытый репозиторий без авторизации, вход пользователя, clone, исходный коммит в истории, контрольная сумма check.txt, новый push, неизменность эталонной конфигурации. Запускается до сбоя, во время сбоя (покажет, что сломано) и после исправления. С аргументом push дополнительно делает новый push с отдельным файлом.

Первый запуск и ручные проверки:
```
cd /opt/task05
./scripts/prepare-demo.sh
./scripts/check.sh push
```
