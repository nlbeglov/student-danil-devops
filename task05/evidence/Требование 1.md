# Требование 1
> Развернуть Gitea, PostgreSQL и Caddy с HTTPS. Закрыть открытую регистрацию. Создать администратора review-admin, обычного пользователя review-user и его закрытый репозиторий demo с двумя коммитами. Проверить clone и push по HTTPS и отказ в анонимном доступе.

## Рабочий стенд
Конфигурация: [.env.example](../configs/.env.example), [docker-compose.yml](../configs/docker-compose.yml), [Caddyfile](../configs/Caddyfile). HTTPS, порты 80/443 и сертификат обслуживает общий Caddy ([common/caddy](../../common/caddy/Caddyfile), блок `a4.fdghyt.com`); Caddy задания (`task05-caddy`) работает по HTTP внутри сети и проксирует на Gitea (`task05-server:3000`) — именно его upstream ломает сбой `proxy`.

Скрипты:
- [lib.sh](../scripts/lib.sh) — общие функции (пути, `.env` и `credentials.txt`, учётные данные git, запросы к API Gitea, журнал);
- [setup-secrets.sh](../scripts/setup-secrets.sh) — создаёт пароли PostgreSQL, `review-admin`, `review-user` в `secrets/credentials.txt`, пароль БД пишет в `configs/.env`; запускать до первого запуска стека;
- [deploy.sh](../scripts/deploy.sh) — поднимает стек и ждёт готовности Gitea;
- [prepare-demo.sh](../scripts/prepare-demo.sh) — создаёт пользователей и закрытый репозиторий `demo`, делает два коммита через HTTPS и фиксирует эталон (`baseline.txt`, `baseline-config.sha256`);
- [check.sh](../scripts/check.sh) — контрольные проверки (девять шагов).

Первый запуск:
```bash
cd /opt/devops/task05/configs && cp .env.example .env && nano .env     # DOMAIN=a4.fdghyt.com
../scripts/setup-secrets.sh
../scripts/deploy.sh
../scripts/prepare-demo.sh
../scripts/check.sh push
```
