# Требование 3
> Подготовить три воспроизводимых изменения: неверный порт Gitea в upstream Caddy; неверное имя хоста PostgreSQL в настройках Gitea; подключение тома данных Gitea в режиме только чтения. Хранить изменения в отдельных Compose override-файлах либо скриптах.

## Сбои хранятся в `configs/faults/` как Compose override-файлы
- [Caddyfile.proxy](../configs/faults/Caddyfile.proxy) — испорченная копия Caddyfile с неверным портом upstream (`task05-server:3001` вместо `3000`);
- [proxy.yml](../configs/faults/proxy.yml) — сбой 1: подменяет Caddyfile в контейнере `task05-caddy` на `Caddyfile.proxy` (тот же путь монтирования, запись заменяется);
- [database.yml](../configs/faults/database.yml) — сбой 2: переопределяет только адрес БД у Gitea, имя хоста `postgres-db` не существует в сети Compose;
- [readonly.yml](../configs/faults/readonly.yml) — сбой 3: тот же том данных Gitea, но в режиме только для чтения (`:ro`).

Скрипты:
- [fault.sh](../scripts/fault.sh) `proxy|database|readonly` — вносит один сбой: пересоздаёт только затронутый сервис (`--no-deps`), данные не трогает, пишет время в [faults.log](faults.log); второй сбой не вносится, пока не выполнен `recover.sh`;
- [recover.sh](../scripts/recover.sh) — возвращает рабочую конфигурацию: пересоздаёт `server` и `caddy` из эталонного `docker-compose.yml` без override, тома и данные не трогает (`down -v` не используется), сверяет эталон с `baseline-config.sha256`.
