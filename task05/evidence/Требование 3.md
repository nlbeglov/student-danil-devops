# Требование 3
> Подготовить три воспроизводимых изменения: неверный порт Gitea в upstream Caddy; неверное имя хоста PostgreSQL в настройках Gitea; подключение тома данных Gitea в режиме только чтения. Хранить изменения в отдельных Compose override-файлах либо скриптах.
## Сбои, восстановление и проверка
Сбои хранятся в `configs/faults/` как Compose override-файлы
- [Caddyfile.proxy](../configs/faults/Caddyfile.proxy) - испорченная копия Caddyfile с неверным портом upstream (3001 вместо 3000)
- [proxy.yml](../configs/faults/proxy.yml) - сбой 1. Подменяет Caddyfile в контейнере Caddy на Caddyfile.proxy (тот же путь монтирования, поэтому запись заменяется, а не добавляется).
- [database.yml](../configs/faults/database.yml) - сбой 2. Переопределяет только переменную с адресом БД у Gitea: имя хоста postgres-db не существует в сети Compose (Compose объединяет environment по имени переменной, остальные остаются прежними).
- [readonly.yml](../configs/faults/readonly.yml) - сбой 3. Тот же том данных Gitea, но в режиме только для чтения (:ro); совпадающий путь монтирования /data заменяет эталонную запись.
Добавление скриптов:
- [fault.sh](../scripts/fault.sh) - вносит один из трёх сбоев. Пересоздаёт только затронутый сервис (--no-deps), данные не трогает, пишет время в журнал. Не даёт внести второй сбой, пока не выполнен recover.sh.
- [recover.sh](../scripts/recover.sh) - возвращает рабочую конфигурацию. Пересоздаёт server и caddy из эталонного docker-compose.yml без override. Тома и данные не трогает (down -v не используется). Работает при любом из трёх сбоев и безопасен при повторном запуске.

Выдаем права скриптам и убеждаемся что до начала тестов система работает испарвно:
```
chmod +x /opt/task05/scripts/*.sh
cd /opt/task05 && ./scripts/check.sh
```
