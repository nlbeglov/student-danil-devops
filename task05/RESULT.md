## 5. Проверка за 5 минут
Действия (на VPS, каталог `/opt/devops/task05`):
1. `./scripts/check.sh push`: исходное состояние стенда.
2. `./scripts/fault.sh proxy` (либо `database`, либо `readonly`): внести сбой.
3. `./scripts/check.sh`: убедиться, что сбой заметен (502).
4. Диагностика: `cd configs && docker compose logs --tail 20 caddy` (для `database` и `readonly` смотреть `logs server`).
5. `./scripts/recover.sh`, затем `./scripts/check.sh push`.

Ожидаемый результат:
- шаг 1: «все проверки пройдены», в выводе hash `b5d32d9e96d30988d5a3322a6fd0e0ceebcdbea3` и сумма `check.txt` `7e7733ff…bef29`;

## Проблемы и ограничения
- Стенд работает за общим Caddy: домен `a4.fdghyt.com`, HTTPS и порты 80/443 обслуживает `common/caddy`, задания работают одновременно. Собственный Caddy задания (`task05-caddy`) работает по HTTP внутри сети: его upstream ломает сбой `proxy`.
- Имя Gitea в сети `edge` для Caddy задания — `task05-server`: имя сервиса `server` встречается и у задания 01, без уникального имени Caddy иногда попадал в чужой Gitea и вход давал 401.
- Закрытость портов 3000 и 5432 проверена реальным запросом с таймаутом с другого сервера: `nc -zv` из некоторых сетей показывает «succeeded» из-за особенностей сети, хотя ответа сервиса нет.
- Проверка «анонимный clone отклонён» учитывает сохранённые учётные данные git: в `lib.sh` credential helper'ы отключены.
- Оставшиеся работы: нет.
