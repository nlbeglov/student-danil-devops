## 5. Проверка за 5 минут
Действия (на VPS, каталог `/opt/devops/task03/configs`):
1. `curl -s https://[домен]/a.txt` — файл отдаётся по HTTPS.
2. `restic -r "$RESTIC_REPOSITORY" snapshots` — три снимка во внешнем хранилище; `systemctl list-timers task03-backup.timer` — расписание и последнее срабатывание.
3. `cd configs && docker compose stop && ../scripts/restore.sh` — восстановление из внешнего хранилища в проект `task03-restore`.
4. `../scripts/check.sh` — сравнение manifest, чтение файлов, запись `id=101`, ошибка доступа к хранилищу.
5. `(cd ../restore/configs && docker compose stop) && docker compose up -d` — вернуть основной стенд.

Ожидаемый результат:
- шаг 2: ровно три снимка, таймер активен;
- шаг 4: «ИТОГ: все проверки пройдены»: manifest совпадает (100 строк, SHA-256 выгрузки и файлов), `id=101` записана, `backup.sh` с неверным паролем завершился с ненулевым кодом, в `evidence/backup.log` строка `FAILED`.

## Проблемы и ограничения
- Задание не прогонялось на VPS: нет вывода команд в `evidence/`, не заполнены часы, домен, хранилище и показатели.
- Блокировка записи реализована через `default_transaction_read_only = on` для новых подключений к БД; уже открытые соединения этот запрет не затрагивает; тестовых записей во время копирования нет по условиям опыта.
- Доступ к хранилищу по SFTP настраивается один раз вручную (`setup-storage.sh`); ключ restic нельзя восстановить, при его потере копии не прочитать.
