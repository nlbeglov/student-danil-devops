# Требование 6
> Сравнить manifest до и после восстановления. Проверить чтение файлов и запись новой строки с id=101 в восстановленную БД. Отдельно вызвать ошибку доступа к хранилищу: скрипт должен завершиться с ненулевым кодом и зафиксировать неуспех. После проверки вернуть рабочие настройки.

## Ход работы
[check.sh](../scripts/check.sh) выполняет проверки подряд: `restic check` и число снимков (3), последнее срабатывание таймера, `diff` manifest до/после, чтение `a.txt`, `b.txt`, `c.txt`, запись и чтение `id=101` в восстановленной БД, `backup.sh` с неверным паролем restic (ненулевой код и `FAILED` в `evidence/backup.log`). Неверный пароль передаётся только переменной окружения одного запуска, рабочие настройки не меняются.

```bash
./scripts/check.sh                            # после restore.sh
cd restore/configs && docker compose stop     # остановить восстановленный проект
cd /opt/devops/task03/configs && docker compose up -d   # вернуть основной стенд
```
Фактический вывод: _приложить после запуска на VPS_.
